## turn — assistant 2026-08-06T19:51:49-07:00

**`.olean`** is the compiled module — "object Lean". You can see its magic header: `olean`, format version `2`, toolchain `4.32.2`. It is a serialized image of the environment the module produces: every declaration with its type and its *proof term*, plus instances, attributes and simp entries. This is what `import` loads, and it is loaded by `mmap` read-only — which is exactly why my memory measurements had to use PSS rather than summed RSS. Twenty Lean workers mapping the same Mathlib `.olean`s share those pages; counting them per process inflated the whole-library figure from 2.3 GiB to 11.8 GiB. It is also the artifact whose deletion forces re-elaboration; `touch` does nothing, because Lake traces content hashes.

**`.ilean`** is the interactive index — "interactive Lean", consumed by the language server, not the compiler. It is plain JSON: a map from each declaration's fully-qualified name to source positions, as you can see for `ScottDomains.Plotkin.FinCompacts`, with ranges for the declaration and its identifier. That is what powers go-to-definition, find-references and document symbols in VS Code or `lean4-mode`. Delete it and the build is unaffected; only the editor loses navigation.

**`.trace`** is Lake's staleness record — the input hashes that decide whether the module needs rebuilding.

| # | File | Size for `Plotkin.lean` (387 lines) | Read by | Needed to build? |
| -- | ---- | ----------------------------------- | ------- | ---------------- |
| 1 | `.olean` | 254,504 B | the compiler, on `import` | yes |
| 2 | `.ilean` | 35,522 B | the language server | no |
| 3 | `.trace` | 2,955 B | Lake | for incrementality only |
