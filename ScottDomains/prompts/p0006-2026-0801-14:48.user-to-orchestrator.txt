The Emacs agent finished — **dirtrack is fixed and verified**. The root cause was subtle and worth stating precisely:

**Root cause:** zsh's line editor repaints the prompt prefixed with a **carriage return** (`\r`), so the chunk dirtrack saw was `"\r/…/ScottLean4 % "`. The old regexp `^\([^ ]+\) [#%] ` anchored `^` *before* the `\r` and `[^ ]+` happily swallowed the `\r` (a CR isn't a space), so the captured string was `"\r…/ScottLean4"` — which `file-name-absolute-p` rejects (doesn't start with `/`). dirtrack therefore skipped the cd. Not the tilde, not `comint-process-echoes` — the leading CR.

**Fix (two coupled edits):**
- `~/.zshrc` in-Emacs prompt: `%~ %# ` → **`%d %# `** (emit the absolute path so the capture always starts with `/`).
- `~/.emacs` dirtrack regexp: `^\([^ ]+\) [#%] ` → **`\(/[^ \r\n]*\) [#%] `** (capture from the literal `/`, excluding CR/space/newline; no `^` anchor).
