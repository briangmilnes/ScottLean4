## The crux

`ScottHom.lean` defines `sSup` by a `dite` on **continuity of the pointwise supremum** — not on directedness — and the docstring says why deliberately:

> Directedness and boundedness are then two *sufficient* conditions, neither privileged in the definition.

A complete-lattice codomain is a **third** such condition. Suprema commute, `⨆ᵢ ⨆ₓ = ⨆ₓ ⨆ᵢ`, unconditionally in a complete lattice — so the pointwise sup of an *arbitrary* set of Scott-continuous maps is continuous, with no directedness and no boundedness. The `dite` therefore always takes the positive branch and the `const ⊥` junk value never fires.

The consequence that matters: **no second `SupSet`, so no `SupSet` diamond** — the hazard `ScottHom.lean` records as having broken an `Iff.rfl` in r0004. And in Lean it's one application of the package's own `scottContinuous_pointwiseSup_of_forall_isLUB`, which was written without directedness precisely to allow this.

## One judgment call

`scottHomCompleteLattice` is a **`def`, not an `instance`**. Mathlib's `completeLatticeOfSup` documents itself as having "bad definitional properties": it sets `bot := sSup ∅`, while the package's `CompletePartialOrder (ScottHom α β)` sets `bot := const ⊥`. Those agree *propositionally* but not definitionally, and registering it globally would put an `OrderBot` diamond across a 1538-job library. Opt in with `letI`.

Proving `sSup ∅ = const ⊥` and hand-rolling `bot` would make it a safe instance — small, and the obvious next step.

## Two Lean details

`PartialOrder.lift` leaves a beta-redex, so the `IsLUB` proof needs `dsimp only` before `rw` — exactly as the package's own `lubOfDirected` does. And a `def` whose type is a class must be `@[reducible]`.
